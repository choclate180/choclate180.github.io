01

Overview

The source images contain three exposures of the same scene, captured through blue, green, and red filters and stacked vertically. My goal in this project is to use image processing techniques for producing color images based off of Prokudin-Gorskii's RGB glass plates.

02

Alignment and Metrics

I effectively treated the blue exposure as a fixed reference piece and found the translations that best aligned the green and red exposures to it.

02 · Metrics

Normalized Cross-Correlation

NCC(a,b)= a^·b^ ‖a^‖2‖b^‖2

NCC compares the direction of two mean-centered pixel arrays. A larger value indicates a stronger match. This was the metric used for the final results; it evaluates the dot product of the mean-subtracted arrays, which is then divided by the product of their L2 norms to normalize the result. Since np.roll wraps pixels around the image boundaries, I calculated each score using only the interior 80% of the image. Ignoring the outer 10% on every side prevents the plate borders and wrapped pixels from influencing NCC.

L2 Distance

L2(a,b)=‖a−b‖2

L2 directly measures pixel differences, where a smaller value is better. I implemented it but used NCC for the results shown below. I avoided L2 since it measures the absolute difference in raw pixel strength rather than accounting for images with objects that have vastly different brightness values across color channels. Thus, NCC was the ideal method for almost all the images.

03 · Search

Single-Scale Search

For the smaller JPEGs, I used a straightforward exhaustive search. The algorithm takes the original image and slides it around within a fixed [-15, 15] pixel window. At every single (x, y) stop, it calculates the NCC score to see how well the channels line up. Then it picks the shift that yields the highest score.

Image Pyramid

Doing an exhaustive search on the high-resolution TIFF files would take forever. To fix this, I built an image pyramid, with ideas covered in discussion. The algorithm first shrinks the image down by averaging 2x2 blocks of pixels until its largest dimension is under 300 pixels. It runs the standard [-15, 15] search on this tiny version to get a rough estimate. Then, it scales that estimate up by 2 and moves up to the next resolution level, doing a tiny [-3, 3] search to refine the alignment. It repeats this until it reaches the full original resolution, saving lots of time computationally.
